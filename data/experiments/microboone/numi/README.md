# MicroBooNE NuMI data boundary

This directory contains visible diagnostic NuMI inputs and a disabled
four-channel empirical adapter.  It does not enable the NuMI likelihood because
the response is borrowed from BNB and the joint statistical treatment is not
validated.

## Visible inputs

`inputs/flux_components/` contains eight CSV files:

- FHC and RHC separately;
- `numu`, `numubar`, `nue`, and `nuebar` separately;
- 50 bins from 0 to 5 GeV in 0.1 GeV steps;
- flux units of neutrinos/POT/cm2/100 MeV.

These files are copied from the audited PDF-vector extraction output. They are
human-readable approximations to the displayed New Flux curves, not official
unpublished ROOT arrays.

## Regenerable spectrum checks

`outputs/spectra/microboone/numi/flux_components.png` is generated by reading
only the eight copied CSV files. Its same-stem CSV records the shape and SHA-256
of every plotted file, and its metadata JSON records the status and boundary.
Nothing under `outputs/` is used as a numerical input.

## Paper-point weighted flux

`derived/paper_figure3_weighted_flux/` contains four final flavor CSV files.
Each has a no-oscillation column and columns for both Figure 3 parameter points:

- delta_m2_41_eV2 = 1.2;
- sin2(2theta_mue) = 0.003;
- sin2_theta24 = 0.018 or 0.0045.

FHC and RHC per-POT fluxes are exposure averaged with weights 0.308 and 0.692.
The oscillation calculation uses the existing exact 3+1 model at a declared
single NuMI baseline of 0.680 km. This is a flux-level diagnostic; it does not
include the production-position distribution, detector response, efficiency,
cross section, selected data, or covariance, and therefore must not be called a
validated NuMI event prediction or likelihood input.

Run from the repository root:

```powershell
python scripts/experiments/microboone/numi/plot_flux_inputs.py
python scripts/experiments/microboone/numi/build_paper_weighted_flux.py
```

## Isolated four-channel event diagnostic

`reweighting/` is built from released NuMI channels
8--11 (one-based): nue CC FC/PC and numu CC FC/PC.  Its covariance is a 4x4
channel-block matrix, with 26x26 numerical entries in each block, hence 104x104
numbers in the visible CSV.  The adapter reads the existing BNB 26x60 normalized
Reco matrices without changing them, maps the NuMI 0.1 GeV flux bins onto the
Reco 0.05 GeV grid, and constructs the same empirical per-reconstructed-bin
reference-ratio kernel used in the BNB diagnostic.

The principal regenerable output is
`outputs/spectra/microboone/numi/paper_parameter_event_counts.csv`. It contains the
published Data, Background, derived Signal, Signal+Background, exact empirical
reference closure, both paper-point event predictions, and all eight oscillated
source-to-final-flavour contributions for every reconstructed bin.

The reusable covariance is stored under `derived/`, while the true-energy grid,
fixed background, eight response-count kernels, metadata and reference closure
follow the BNB contract under `reweighting/`.

```powershell
python scripts/experiments/microboone/numi/build_four_channel_events.py
```

This remains outside the active likelihood.  In particular, the borrowed Reco
grid ends at 3 GeV although the reconstructed PDF flux extends to 5 GeV, and the
released aggregate Background cannot yet be oscillated component by component.
